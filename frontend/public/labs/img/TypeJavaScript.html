TypeScript vs JavaScript

A Evolução da Linguagem: Tipagem Estática, Ecossistema e Produtividade

🔷 1. Conceito Fundamental e Superset

O JavaScript (JS) é uma linguagem interpretada de dinâmica fraca, fundamental para a Web. O TypeScript (TS) é um superset genérico de JavaScript desenvolvido pela Microsoft, adicionando checagem estática de tipos e recursos avançados antes mesmo de serem compilados para JS puro.

1
Superset Válido: Todo código JavaScript é, por definição, um código TypeScript válido. Você pode renomear arquivos de .js para .ts sem quebrar a execução.
2
Processo de Transpilação: Os navegadores e ambientes de execução (como Node.js ou Runtimes WEB) não executam TypeScript diretamente. O compilador tsc remove todas as anotações de tipo e gera JavaScript puro.
3
Detecção Erros em Tempo de Compilação: Enquanto o JS identifica erros de tipo apenas durante a execução (runtime), o TS captura falhas no momento da escrita/compilação (compile-time).
💻 2. Comparativo de Código: JS vs TS

A principal diferença está na definição de contratos explícitos (interfaces e tipos) que evitam comportamentos inesperados ao manipular objetos e funções.

// ========================================== // 1. Exemplo em JavaScript (Dinâmico / Sem Tipos) // ========================================== function calcularTotalJS(preco, quantidade) { return preco * quantidade; } // Risco: Aceita argumentos inválidos sem avisar na compilação const resultadoJS = calcularTotalJS("100", undefined); // Retorna NaN silenciosamente // ========================================== // 2. Exemplo em TypeScript (Estático e Seguro) // ========================================== interface Produto { id: number; nome: string; preco: number; } function calcularTotalTS(produto: Produto, quantidade: number): number { return produto.preco * quantidade; } // O editor acusa erro imediatamente se os tipos forem violados const item: Produto = { id: 1, nome: "Teclado Mechanical", preco: 250.00 }; const total = calcularTotalTS(item, 2); // Retorna 500 (Segurança garantida)
⚙️ 3. Estrutura de Configuração (tsconfig.json)

O arquivo tsconfig.json é a espinha dorsal de um projeto TypeScript. Ele dita as regras de verificação do compilador, alvo da versão JS emitida e caminhos de importação.

{ "compilerOptions": { "target": "ES2022", /* Versão do JavaScript gerada no build */ "module": "ESNext", /* Sistema de módulos (ESM) */ "strict": true, /* Ativa checagem rigorosa de tipos (Recomendado) */ "noImplicitAny": true, /* Impede variáveis sem tipo definido implicitamente */ "moduleResolution": "bundler", /* Resolução compatível com bundlers modernos (Vite, Webpack) */ "outDir": "./dist", /* Pasta de destino dos arquivos JS compilados */ "baseUrl": ".", "paths": { "@/*": ["src/*"] /* Mapeamento de Path Aliases */ } }, "include": ["src/**/*"] }
📊 Comparativo Direto: TypeScript vs JavaScript
Característica JavaScript TypeScript
Sistema de Tipos Dinâmico e fraco (tipos resolvidos em tempo de execução). Estático e forte (tipos checados em tempo de compilação).
Detecção de Erros Apenas em tempo de execução (podendo causar crashes em produção). Em tempo de desenvolvimento/compilação diretamente na IDE.
Autocompletar / Autocompletion Limitado ou baseado em inferência básica do editor. Extremamente preciso devido aos contratos explícitos e interfaces.
Refatoração Sujeita a erros e dependente de buscas globais manuais no código. Segura e automatizada; alterar uma interface atualiza/avisa todas as referências.
Curva de Aprendizado Menor, ideal para prototipagem e scripts rápidos. Moderada, exige aprendizado de sintaxe de tipos, generics e POO.
Suporte do Navegador Nativo em todos os navegadores e ambientes de runtime. Requer compilação/transpilação para JavaScript antes da execução.

APIs / Backends Complexos TypeScript Garante o cumprimento dos esquemas de dados recebidos e enviados pelo banco/cliente.
