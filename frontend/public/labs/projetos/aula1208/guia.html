JSON JavaScript Object Notation

JSON é um formato leve de troca de dados, altamente legível tanto para humanos quanto para máquinas. Originou-se da sintaxe de objetos do JavaScript, mas hoje é independente e suportado por quase todas as linguagens de programação.

Regras de Sintaxe

  • Dados são armazenados em pares "chave": valor.
  • As chaves devem ser envolvidas por aspas duplas.
  • Objetos são delimitados por chaves {}.
  • Arrays (listas) são delimitados por colchetes [].
  • Não permite vírgula no último item (Trailing Comma).

Tipos de Dados Suportados

  • String: "Texto"
  • Number: 42 ou 3.14
  • Boolean: true ou false
  • Null: valor nulo
  • Object: { ... }
  • Array: [ ... ]

Aplicações Práticas

Comunicação em APIs RESTful, bancos de dados NoSQL (como MongoDB), arquivos de configuração de projetos (ex: package.json).

XML Extensible Markup Language

XML é uma linguagem de marcação focada na flexibilidade e na validação rigorosa de dados. Diferente do HTML, o XML não possui tags pré-definidas; o desenvolvedor cria os elementos de acordo com o domínio do problema.

Regras de Sintaxe

  • É obrigatório ter uma única tag raiz envolvendo todo o documento.
  • Toda tag de abertura deve ter sua respectiva tag de fechamento (ex: <item>...</item>).
  • Atributos em tags devem ter seus valores entre aspas (ex: id="1").
  • É case-sensitive (diferencia maiúsculas de minúsculas).

Recursos Avançados

  • Atributos: Permitem metadados na própria tag.
  • Schemas (XSD): Permite validar se o arquivo segue regras rígidas.
  • Namespaces: Evitam conflito de nomes de tags.
  • CDATA: Blocos para inserir caracteres especiais sem parsing.

Aplicações Práticas

Sistemas legados e corporativos, integração bancária, Feeds RSS, Nota Fiscal Eletrônica (NF-e no Brasil) e arquivos de configuração Java/Android.

CSV Comma-Separated Values

O CSV é o formato tabular mais simples e antigo. Ele armazena dados em texto plano, onde cada linha do arquivo representa um registro/linha da tabela, e os campos são separados por um caractere delimitador (geralmente vírgula ou ponto e vírgula).

Regras de Sintaxe

  • A primeira linha normalmente contém os cabeçalhos das colunas.
  • Valores que contêm o próprio delimitador ou quebras de linha devem estar entre aspas duplas.
  • Não suporta nativamente estruturas aninhadas/hierárquicas.
  • Não guarda tipos de dados (tudo é lido como texto originalmente).

Variações & Cuidados

  • Delimitadores: Na Europa/Brasil usa-se muito o ponto e vírgula (;) pois a vírgula é usada como separador decimal.
  • Codificação: Requer atenção com UTF-8 para evitar problemas com acentuação.

Aplicações Práticas

Exportação/importação de relatórios em planilhas (Excel, Google Sheets), Ciência de Dados, Machine Learning e migração de bancos de dados relacionais.

YAML YAML Ain't Markup Language

YAML é um formato focado na máxima legibilidade humana. Ele elimina o excesso de chaves, colchetes e tags, utilizando indentação por espaços para definir a hierarquia e estrutura dos dados.

Regras de Sintaxe

  • Sensível à indentação (devem ser usados espaços, nunca a tecla Tab).
  • Listas são iniciadas com hífen e espaço (- item).
  • Pares chave-valor usam dois pontos e espaço (chave: valor).
  • Permite comentários nativos iniciados com #.

Vantagens Principais

  • Extremamente limpo e fácil de ler/editar manualmente.
  • Suporta comentários (o que o JSON não permite).
  • Mapeia os mesmos tipos de dados complexos que o JSON.

Aplicações Práticas

Arquivos de configuração de DevOps e infraestrutura (Docker Compose, Kubernetes, GitHub Actions, Ansible) e pipelines de CI/CD.
