Ferramenta Frontend de Nova Geração: Características, Estrutura e Uso Prático

⚡ 1. O que é o Vite e suas Características Básicas

O Vite (palavra em francês para "rápido") é um build tool moderno focado em otimizar drasticamente a experiência de desenvolvimento frontend. Ele resolve a lentidão de bundlers tradicionais (como Webpack e Rollup) dividindo o ecossistema em duas fases essenciais:

1
Servidor de Desenvolvimento Ultrarrápido: Utiliza ES Modules (ESM) nativos do navegador para carregar o código sob demanda, além de pré-bundlar dependências via esbuild (escrito em Go, até 100x mais rápido que bundlers JS).
2
Hot Module Replacement (HMR) Instantâneo: Quando um arquivo é alterado, apenas o módulo modificado é trocado no navegador, mantendo o estado da aplicação sem recarregar a página inteira.
3
Build de Produção Otimizado: Utiliza Rollup altamente configurado sob o capô para gerar assets estáticos minificados, com splitting de código e tree-shaking eficientes.
🚀 2. Como Usar: Criando um Projeto do Zero

A inicialização de um projeto com Vite é feita diretamente pelo CLI usando o gerenciador de pacotes de sua preferência (npm, yarn ou pnpm). O scaffolding permite escolher templates para Vanilla JS, React, Vue, Svelte, Lit ou Solid (com suporte nativo a TypeScript).

# 1. Criar um novo projeto interativo npm create vite@latest meu-app-vite # Ou especificar a tecnologia diretamente pelo comando: npm create vite@latest meu-app-react -- --template react-ts # 2. Acessar o diretório do projeto cd meu-app-vite # 3. Instalar as dependências npm install # 4. Iniciar o servidor de desenvolvimento npm run dev
📂 3. Estrutura Padrão de Diretórios

Diferente de bundlers tradicionais onde o arquivo index.html fica escondido na pasta public, no Vite o index.html fica na raiz do projeto e atua como o ponto de entrada principal (entry point) da aplicação.

# Árvore de Diretórios de uma Aplicação Vite (React / TS) meu-app-vite/ ├── index.html <-- Entry point principal da aplicação (contém <script type="module" src="/src/main.tsx">) ├── package.json <-- Scripts de execução e dependências ├── vite.config.ts <-- Arquivo central de configuração de plugins, aliases e proxy ├── public/ <-- Assets estáticos não processados servidos na raiz (favicons, robots.txt) └── src/ ├── main.tsx <-- Script inicial que monta a árvore do React/DOM ├── App.tsx <-- Componente raiz da aplicação ├── App.css <-- Estilos do componente └── assets/ <-- Imagens e ícones que passam pela pipeline do Vite
⚙️ 4. Configuração e Mapeamentos (vite.config.ts)

O arquivo vite.config.ts centraliza os plugins da framework, atalhos de importação (path aliases) e configurações do servidor dev (como portas e proxies para APIs backend).

import { defineConfig } from 'vite'; import react from '@vitejs/plugin-react'; import path from 'path'; // Configuração do Vite export default defineConfig({ plugins: [react()], // Configurações do Servidor de Desenvolvimento server: { port: 3000, open: true, // Abre o navegador automaticamente // Redirecionamento de chamadas de API (Proxy para Backend) proxy: { '/api': { target: 'http://localhost:8080', changeOrigin: true, } } }, // Configuração de Path Aliases (Simplifica imports com '@/') resolve: { alias: { '@': path.resolve(__dirname, './src'), }, }, });
🔑 5. Variáveis de Ambiente e Scripts do package.json

O Vite utiliza o padrão Dotenv para variáveis de ambiente, mas com uma regra de segurança estrita: apenas variáveis prefixadas com VITE_ são expostas ao código do cliente.

# Arquivo: .env (Na raiz do projeto) VITE_API_URL=https://api.professor-anderson.com VITE_APP_TITLE="Meu App com Vite" # Arquivo em código TypeScript/JavaScript (Ex: src/App.tsx) const apiUrl = import.meta.env.VITE_API_URL; console.log(`Conectado em: ${apiUrl}`);
Comando / Script Ação Executada Uso Prático
npm run dev Inicia o servidor dev local com HMR na porta configurada (padrão 5173). Desenvolvimento diário com reload instantâneo.
npm run build Executa a compilação do Rollup e gera os estáticos minificados na pasta /dist. Geração da versão final para deploy.
npm run preview Sobe um servidor local para testar a pasta de produção /dist. Validação pré-deploy do bundle final.
📊 Comparativo: Vite vs Bundlers Clássicos (Webpack / CRA)
Característica Vite Webpack / Create React App
Inicialização Dev Instantânea (servidor levanta sem empacotar tudo antes). Lenta (precisa fazer o bundle de toda a aplicação em memória).
Velocidade de HMR Constante (não degrada conforme o projeto cresce). Fica mais lento à medida que o número de módulos aumenta.
Ponto de Entrada index.html na raiz tratado como arquivo de código. Scripts JavaScript/TypeScript internos mapeados via config complexa.
Variáveis Globais Acessadas via import.meta.env. Acessadas via process.env.
