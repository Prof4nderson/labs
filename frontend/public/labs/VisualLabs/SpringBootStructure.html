Spring Boot Basics

Estrutura de Pastas, Controllers, Services, Repositories e Models

📂 1. Estrutura Padrão de Pastas (Maven / Gradle Layout)

O ecossistema Spring Boot adota o padrão de convenção sobre configuração. O projeto é estruturado a partir da raiz do repositório src/main/java, organizando o código fonte em pacotes específicos de acordo com a responsabilidade arquitetural de cada classe.

# Árvore de Diretórios de uma Aplicação Spring Boot Padrão src/ └── main/ ├── java/ │ └── com/app/demo/ │ ├── DemoApplication.java <-- Ponto de entrada anotado com @SpringBootApplication │ ├── controllers/ <-- Camada Web REST (HTTP Requests / Responses) │ ├── services/ <-- Camada de Negócio (Lógica da aplicação, validações) │ ├── repositories/ <-- Camada de Persistência (Spring Data JPA / SQL) │ ├── models/ <-- Camada do Domínio (Entidades mapeadas para o BD) │ └── dtos/ <-- Data Transfer Objects (Contratos de Entrada e Saída) └── resources/ ├── application.properties <-- Configurações de banco, porta e propriedades ├── static/ <-- Arquivos estáticos (CSS, JS, Imagens) └── templates/ <-- Templates HTML (Thymeleaf, caso aplicável)
📦 2. Model / Entity (Mapeamento Objeto-Relacional)

A camada Model (ou Entity) representa as estruturas de dados do sistema. No Spring Data JPA, essas classes são anotadas com @Entity para indicar que cada instância da classe corresponde a uma linha de uma tabela no Banco de Dados Relacional.

package com.app.demo.models; import jakarta.persistence.*; @Entity @Table(name = "tb_produtos") public class Produto { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id; @Column(nullable = false) private String nome; private Double preco; // Construtor padrão exigido pelo JPA public Produto() {} // Construtor completo public Produto(Long id, String nome, Double preco) { this.id = id; this.nome = nome; this.preco = preco; } // Getters e Setters public Long getId() { return id; } public void setId(Long id) { this.id = id; } public String getNome() { return nome; } public void setNome(String nome) { this.nome = nome; } public Double getPreco() { return preco; } public void setPreco(Double preco) { this.preco = preco; } }
🗄️ 3. Repository (Acesso a Dados com Spring Data JPA)

A camada Repository é composta por interfaces que estendem JpaRepository. O Spring Data JPA fornece automaticamente implementações em tempo de execução para operações CRUD completas (save, findById, findAll, deleteById) e suporte a métodos de busca derivados (*Derived Query Methods*).

package com.app.demo.repositories; import com.app.demo.models.Produto; import org.springframework.data.jpa.repository.JpaRepository; import org.springframework.stereotype.Repository; import java.util.List; @Repository public interface ProdutoRepository extends JpaRepository<Produto, Long> { // O Spring gera automaticamente o SQL correspondente ao nome do método List<Produto> findByNomeContainingIgnoreCase(String nome); List<Produto> findByPrecoLessThan(Double preco); }
⚙️ 4. Service (Lógica de Negócio e Injeção de Dependência)

A camada Service concentra as regras de negócio, validações do sistema e controle transacional. É anotada com @Service para ser reconhecida pelo container Spring como um Bean e injetada onde necessário.

package com.app.demo.services; import com.app.demo.models.Produto; import com.app.demo.repositories.ProdutoRepository; import org.springframework.beans.factory.annotation.Autowired; import org.springframework.stereotype.Service; import java.util.List; @Service public class ProdutoService { @Autowired private ProdutoRepository repository; public List<Produto> listarTodos() { return repository.findAll(); } public Produto salvar(Produto produto) { // Regra de negócio: Validação do preço do produto if (produto.getPreco() != null && produto.getPreco() < 0) { throw new IllegalArgumentException( "O preço do produto não pode ser negativo." ); } return repository.save(produto); } }
🌐 5. Controller (Endpoints da API REST e Protocolo HTTP)

A camada Controller expõe a aplicação para o mundo externo através de APIs RESTful. Anotada com @RestController, intercepta requisições HTTP, realiza o parse dos parâmetros de entrada e devolve dados serializados em JSON junto aos códigos de status HTTP apropriados.

package com.app.demo.controllers; import com.app.demo.models.Produto; import com.app.demo.services.ProdutoService; import org.springframework.beans.factory.annotation.Autowired; import org.springframework.http.HttpStatus; import org.springframework.http.ResponseEntity; import org.springframework.web.bind.annotation.*; import java.util.List; @RestController @RequestMapping("/api/produtos") public class ProdutoController { @Autowired private ProdutoService service; @GetMapping public ResponseEntity<List<Produto>> listar() { List<Produto> lista = service.listarTodos(); return ResponseEntity.ok(lista); } @PostMapping public ResponseEntity<Produto> criar(@RequestBody Produto produto) { Produto novo = service.salvar(produto); return ResponseEntity .status(HttpStatus.CREATED) .body(novo); } }
📊 Resumo das Camadas e Mapeamento de Atribuições
Camada Anotação Principal Responsabilidade Comunica-se Com
Controller @RestController Gerenciamento de rotas, serialização JSON e códigos HTTP. Cliente HTTP $\rightarrow$ Service
Service @Service Regras de negócio, cálculos, validações e transações. Controller $\rightarrow$ Repository
Repository @Repository Execução de instruções SQL / JPQL e persistência. Service $\rightarrow$ Banco de Dados
Model @Entity Representação em memória das tabelas e relacionamentos. Mapeada em todas as camadas
🔄 Fluxo de Execução End-to-End (Uma Requisição HTTP)
1
Client HTTP (Navegador / Postman / Mobile): Envia uma requisição (ex: POST /api/produtos com um corpo JSON).
2
Controller: O método anotado com @PostMapping recebe o JSON, desserializa para a classe Produto e delega a chamada para a camada de serviço.
3
Service: Executa os critérios de negócio (valida se o preço é maior que zero). Se aprovado, repassa o objeto para a camada de persistência.
4
Repository: Invoca o método save() do JpaRepository. O Hibernate traduz o método Java em uma instrução SQL INSERT INTO tb_produtos ....
5
Banco de Dados & Retorno: O BD persiste os dados, gera a chave primária e retorna ao Controller, que responde ao cliente com o código HTTP 201 Created e o JSON gravado.
