🐳 1. O que é o Docker e Conceitos Fundamentais

O Docker é uma plataforma open-source de containerização que permite empacotar uma aplicação e todas as suas dependências (código, runtime, bibliotecas do sistema e configurações) em uma unidade padronizada chamada Container. Diferente das Máquinas Virtuais (VMs), os containers compartilham o Kernel do sistema operacional do Host, tornando-os extremamente leves, rápidos de inicializar e altamente portáveis.

1
Imagem (Docker Image): Modelo somente leitura (*read-only template*) que contém as instruções para criar um container. Funciona como a classe/blueprint do sistema.
2
Container: Instância em execução de uma Imagem. Possui seu próprio sistema de arquivos isolado, portas de rede e processos, mas consome recursos diretamente do Kernel do host.
3
Docker Registry (Docker Hub): Repositório remoto onde imagens públicas ou privadas são armazenadas e distribuídas através de comandos de pull e push.
📄 2. Anatomia de um Dockerfile (Multi-Stage Build)

O Dockerfile é o script de automação usado para construir uma imagem Docker personalizada. A técnica de **Multi-Stage Build** permite compilar o código em um estágio pesado e copiar apenas o binário/estáticos finais para uma imagem leve em produção.

# --- ESTÁGIO 1: Build da Aplicação --- FROM node:20-alpine AS builder WORKDIR /app # Copia os arquivos de pacotes para aproveitar o cache das camadas COPY package*.json ./ RUN npm ci # Copia o código fonte e gera a build de produção COPY . . RUN npm run build # --- ESTÁGIO 2: Runner de Produção (Imagem Mínima) --- FROM nginx:alpine AS runner # Copia apenas os arquivos finais do estágio de build para o servidor Nginx COPY --from=builder /app/dist /usr/share/nginx/html # Expõe a porta interna do container EXPOSE 80 # Comando executado ao inicializar o container CMD ["nginx", "-g", "daemon off;"]
🐙 3. Orquestração Multi-Container (docker-compose.yml)

O Docker Compose permite definir e rodar aplicações multi-container através de um único arquivo declarativo docker-compose.yml. É ideal para conectar o frontend, backend e banco de dados em uma rede privada isolada.

version: '3.8' services: web_frontend: build: context: . dockerfile: Dockerfile container_name: frontend_app ports: - "8080:80" # Mapeamento de portas (Host:Container) environment: - NODE_ENV=production restart: always database: image: postgres:15-alpine container_name: postgres_db environment: POSTGRES_DB: app_db POSTGRES_USER: admin POSTGRES_PASSWORD: secret123 volumes: - postgres_data:/var/lib/postgresql/data # Persistência de dados volumes: postgres_data: # Volume gerenciado pelo Docker
💻 4. Guia Rápido de Comandos do Docker CLI
Comando Ação Executada Uso Prático
docker build -t app:1.0 . Constroi uma imagem Docker a partir do Dockerfile local e aplica uma tag. Geração da imagem para implantação.
docker run -d -p 8080:80 app:1.0 Cria e executa um container em segundo plano (*detached*) com mapeamento de porta. Subir o container em um servidor.
docker ps -a Lista todos os containers ativos e inativos no servidor. Verificar status de execução e portas.
docker logs -f <id_container> Exibe os logs do container em tempo real no terminal. Depuração e monitoramento de erros.
docker exec -it <id> sh Abre um shell interativo dentro do container em execução. Inspeção manual do sistema de arquivos.
docker compose up -d Constrói e inicia todos os serviços definidos no docker-compose.yml. Subir toda a pilha da aplicação com um comando.
docker compose down Para e remove containers, redes e volumes gerenciados pelo Compose. Encerrar a infraestrutura local com segurança.
📊 Comparativo: Containers vs Máquinas Virtuais (VMs)
Característica Containers (Docker) Máquinas Virtuais (Hypervisor)
Arquitetura Compartilham o Kernel do sistema operacional do Host. Cada VM possui um Sistema Operacional completo (Guest OS).
Tamanho do Asset Leve (dezenas a centenas de Megabytes). Pesado (dezenas de Gigabytes por SO).
Tempo de Startup Instantâneo (milissegundos a segundos). Lento (minutos para dar boot no SO guest).
Isolamento Isolamento em nível de processo e namespaces. Isolamento completo em nível de hardware.
